# vs-image-viewer · 图像观察器

[English](README.md) | 简体中文

VS Code 图像插件，支持 PNG、JPG/JPEG、RAW/CFA、RGB-IR 和 YUV。左侧为按后缀分类的文件列表，
中间为可缩放的图像浏览器，右侧 Secondary Side Bar 显示当前文件的解析属性。

## 安装与运行

需要 **VS Code 1.106 或更新版本**。该版本开始正式支持 [Secondary Side Bar 扩展容器](https://code.visualstudio.com/updates/v1_106#_view-containers-in-secondary-side-bar)。

- 安装：在扩展面板的 `…` 菜单选择 **Install from VSIX…**，选择项目生成的 `vs-image-viewer-x.x.x.vsix`。
- 开发：用 VS Code 打开本目录，按 **F5**，选择“运行图像观察器”。无需安装 npm 依赖或编译。
- 点击活动栏的图像图标，使用 `+` 导入一个或多个文件。点击文件后，编辑器打开预览并自动显示
  右侧属性面板。
- 在 VS Code 资源管理器中直接打开 `.jpg`、`.jpeg`、`.png`、`.raw`、`.y`、`.yuv`、`.uv` 文件时，默认使用图像观察器，
  并自动加入文件列表。用户或工作区已显式设置的 `workbench.editorAssociations` 优先于插件提供的默认关联。
- 点击预览工具栏的“属性”：辅助侧栏未显示图像属性时展开并切换到图像属性；已经显示图像属性时隐藏整个辅助侧栏。编辑器标题栏和命令面板中的“切换图像属性”行为相同。
- 属性内容跟随当前编辑器标签。切换到普通文本、其他编辑器或关闭所有编辑器后清空属性；切回图像预览时恢复。焦点进入右侧属性输入框时仍保留当前图像属性。
- 也可以右键资源管理器里的任意文件，选择“用图像观察器打开”，或使用 **Reopen Editor With → 图像观察器**。

导入的文件列表会按工作区保存，文件参数仅在当前会话内保留。列表中的 `.PNG`、`.JPG`、`.JPEG` 分别按后缀分组，大小写归一。移除条目只移除列表和对应预览，不删除源文件。PNG/JPG 编码与尺寸从文件读取，属性只读；二进制文件的解析与显示属性可编辑。

## 首次加载时从文件名推导属性

新打开的二进制文件会识别文件名中明确标注的属性，**所有匹配均不区分大小写**。字段顺序不限，可用 `_`、`-`、空格或点分隔。仅匹配文件名，不读取父目录中的标记。重启 VS Code 或重新加载窗口后，会清除上次的文件参数，重新从文件名推导属性；同一会话内切换或重新打开文件仍保留手动调整。PNG/JPEG 仍从文件内容读取属性。

| 属性 | 文件名标记示例 |
| --- | --- |
| 图像尺寸 | `1920x1080`、`1920X1080`、`1920×1080` |
| CFA 阵列（按行排列） | `RGGB`、`BGGR`、`GRBG`、`GBRG`、`RGBI`、`RGIB`、`pattern=IRGB` |
| 像素深度 | `12bit`、`12-bit`、`12bpp`、`depth12`、`bitDepth12`、`RAW12`、`BGGR12` |
| 容器与打包 | `in16`、`container16`、`container16bit`、`packed`、`unpacked` |
| 字节端序 / 对齐 | `LE`、`BE`、`LittleEndian`、`BigEndian`；`LSB`、`MSB` |
| 读取偏移 / pitch（字节） | `offset16`、`readOffset16`、`pitch2048`、`rowPitch2048`、`chromaPitch1024`、`uvPitch1024` |
| YUV 预设 | `I420`、`YV12`、`NV12`、`NV21`、`I422`、`NV16`、`NV61`、`YUYV`、`UYVY`、`I444`、`NV24`、`NV42`、`P010`、`P012`、`P016` |
| 颜色矩阵 / 数值范围 | `BT601`、`BT.709`、`BT2020`；`full`、`limited` |

例如 `capture_BGGR_1920X1080_12BIT_IN16_MSB_BE.RAW` 自动采用 BGGR、1920×1080、12-bit 像素、16-bit 容器、高位对齐和大端。`capture_NV12_1920x1080.yuv` 自动采用 NV12；`capture_P010_1920x1080.bin` 自动采用 10-bit 半平面 YUV、16-bit 容器和高位对齐。

显式字段覆盖预设默认值；缺少标记或同一字段存在冲突时保留该字段默认值，识别到的非法参数由属性面板照常提示。未标注容器时，`packed` 使用像素深度作为容器大小，普通 RAW 则向上取整到完整字节。仅有 `RAW12` 不代表 MIPI RAW12 打包。`LSB`/`MSB` 表示容器内对齐，`LE`/`BE` 表示字节/位流顺序；仅有 `RGBIR` 而没有四字符阵列时无法确定阵列排列。`.y`、`.uv` 仍保留单独平面的含义。不会依据图像内容或文件长度猜测参数。

## RAW / CFA / RGB-IR

未知后缀默认作为 CFA 解释，可以在“图像格式”中改为 YUV。宽高可编辑；文件名含 `320x240` 这样的尺寸时自动采用该尺寸。

- Bayer 提供 RGGB、BGGR、GRBG、GBRG 预设，也支持任意 R/G/B 排列。
- CFA 周期阵列固定为 **2×2**，不提供阵列尺寸配置。在主编辑器顶部工具栏最右侧直接编辑 2×2 网格中的 4 个采样点，每格只接收一个字符，小写自动转大写，必须包含 R、G、B。非 R/G/B/I 字符会触发 1.6 秒闪烁，随后以虚线边框和点状网格标记错误；修正字符或选择预设后清除标记。
- 传感器类型由阵列自动识别：包含 I 时使用 RGB-IR，否则使用普通 CFA，无需手动选择。RGB-IR 的 2×2 阵列包含 **一个 I**，例如 `RG / BI`。实际阵列应以传感器文档为准。
- 工具栏阵列仅在 CFA 图像中显示，并与属性面板的阵列模式双向同步。
- 旧配置中的阵列宽高不再生效；旧的非 4 点阵列会提示错误，需要重新选择 2×2 预设或填写有效阵列。
- RGB-IR 支持 RGB、仅 IR、融合和 RGB/IR 并排显示。“显示通道”位于工具栏右侧。仅 IR 模式直接提取每个 2×2 阵列中的 IR 像素，输出宽高均为原始尺寸的一半；奇数宽高舍去不完整阵列。RGB、融合和并排模式中的每个视图使用原始宽高。融合时，左侧工具栏组末尾显示 IR 透明度滑块：0% 为仅 RGB，100% 为仅 IR。
- 可调黑电平、白电平（0 为位深上限）、曝光和 Gamma。

## 图像重建技术设计

### JPEG 预览边缘与角点

JPEG 预览默认开启 **JPEG 边缘修复**。工具栏左侧的角点图标可切换修复预览与浏览器原始解码；修复生效时，像素读数标为 **预览 RGB8**。PNG、CFA 和 YUV 保留原来的显示流程，源文件不会被修改。

[media/jpeg-preview.js](media/jpeg-preview.js) 根据亮度梯度，沿每隔 45° 的八条射线寻找同区域颜色证据，也能利用角点内部的采样。每个参考区域还必须通过二维平坦性检查。只有解码色度符合两侧区域颜色的混合关系，并且亮度能区分像素属于哪一侧时，才修复色度；亮度在 RGB8 取整误差内保持不变。方向结论冲突、颜色越界、低对比度或证据不足时保留原像素。这是保守的预览估计，无法恢复 JPEG 丢失的全部信息，也不会消除所有压缩伪影或对任意纹理进行锐化。该流程的保护条件独立于 CFA 解马赛克系数文件。

[JPEG 回归测试](test/jpeg-preview.test.js) 将独立 JPEG 解码快照与原始条纹图及 ColorChecker PNG 进行整图逐像素比较，同时覆盖八个角点方向、清晰边缘、平滑渐变、细纹理、透明度和切换文件时的取消处理。计算按行分批让出界面执行时间，每次切换修复都从原始解码重新开始。

### 数据流程与职责划分

二进制预览分为存储解析、图像重建和显示三个阶段。[media/core.js](media/core.js) 按容器大小、像素深度、对齐方式、端序、读取偏移和 pitch 读取样本。CFA 插值前先按黑白电平归一化；完成重建及 RGB/IR 融合后，再应用曝光、Gamma 和 RGB8 输出转换。调整预览参数不会写回源文件。

| 组件 | 职责 |
| --- | --- |
| [src/io.js](src/io.js)、[src/decoder-worker.js](src/decoder-worker.js) | 读取所选帧，在复用的 worker 中解码，编码为无损 PNG，并保留原始采样供查询 |
| [media/core.js](media/core.js) | 校验布局、解包采样、重建 CFA/RGB-IR、转换 YUV 和应用显示变换 |
| [media/demosaic.js](media/demosaic.js) | 检测八方向梯度、按梯度强度插值策略并校验系数 |
| [media/viewer.js](media/viewer.js) | 绘制解码图像、管理缩放和平移，将指针坐标映射到原始采样 |

PNG/canvas 预览为 RGB8，二进制像素查询返回原始 4–32 位整数采样。颜色重建误差直接检查解码结果，不受窗口缩放和浏览器显示缩放影响。普通 PNG/JPEG 使用其编码图像，不经过 CFA 重建。

### Bayer 重建

1. **重建绿色。** 四种标准 Bayer 排列使用 Hamilton–Adams 水平／垂直梯度及二阶差分；缺失红蓝分量按 CFA 相位使用轴向或对角线估计初始化。
2. **细化色差。** 绿色和另一颜色分量共同引导红蓝权重，因此绿色不变的颜色边界也能被检测。边界可信度比较跳变与两侧变化；平滑或不确定区域保留初始估计。
3. **保留实测数据。** 显示变换前，原位置的实测通道值保持不变。边界使用保持 CFA 相位的镜像延拓，权重使用量化步长下限，固定首轮引导值以避免扫描顺序影响；红蓝引导数据只缓存三行。
4. **修正有采样依据的角点。** 下述平坦区域角点模型避免同时跨越两条边平均而产生模糊。其他自定义 CFA 排列及单行、单列图像保留通用邻域插值。

参考 [IPOL 对方向插值与残差解马赛克的分析](https://www.ipol.im/pub/art/2021/358/)及 [Boccuto 等人（2024）](https://doi.org/10.1007/s10851-024-01204-y)的通道内／跨通道保边原则。当前实现是轻量适配，并非完整复现论文的迭代正则化求解器。

### RGB-IR 重建顺序

`RG / BI` 等排列不能仅把 I 标签改成 G 就变成标准 Bayer。可见光预览按以下顺序处理：

1. 依据可见光 RGB 采样补全绿色，包括 I 位置的绿色；以原始 R 相位为基准重采样为标准 Bayer 阵列。
2. 对虚拟 Bayer 阵列应用方向性解马赛克。
3. 计算重建值与可见光实测值之间的差值，沿**原始通道采样阵列**插值传播残差；用邻近原始同色采样范围约束修正值，抑制过冲和行列交错条纹。
4. 对两侧平坦、沿边稳定的锐利直线边界，按原始 2×2 采样单元估计不确定像素的归属，避免产生一列中间混合色；平滑渐变和不稳定邻域保留原有插值。
5. 直接用**原始 RGB 采样**验证角点，在重采样、残差传播和直线边缘修正**之后**应用角点修正，避免后续处理再次将角点混色；原始位置保留实测 RGB 值。

IR 数值既不代替绿色，也不参与可见光边缘或角点可信度计算。仅 IR 模式提取原始半分辨率平面；融合和并排模式保持独立的 IR 插值。各可见光显示模式使用同一份重建 RGB。

### 角点模型与重建边界

角点检测支持 **0°、45°、90°、135°、180°、225°、270°、315°** 八个边界朝向，可识别 **45°、90°、135°** 夹角。轴向角点先检查四个 4×4 象限；斜向候选在 12×12 窗口内用两条边界线划分区域，并根据原始数据验证恰好落在对角线上的采样应归属哪一侧。每个分区、每个可见光通道都至少需要两个采样。三个平坦区域的背景颜色须一致，第四个区域至少有两个通道明显不同；若某个可见光通道出现第三种明显不同的值，则提前拒绝斜向双色模型。判定只使用原始采样，解码器不使用测试文件名、已知色块坐标或参考色值。

轴向角点的 Bayer 修正覆盖 6×6 邻域，RGB-IR 覆盖验证过的 8×8 邻域。斜向修正在 12×12 采样依据内覆盖 8×8 像素，以适应旋转插值扩大后的影响范围。预检测比较中心与同相位邻居，即使尖角两端都是背景也能检测到中心的变化。RGB-IR 会在 I 锚点周围额外搜索可见光相位，并从模型检查中排除 I。同优先级模型发生冲突时保留现有估计。修正强度遵循方向与梯度策略，`uniform = 1` 时禁用此锐化。

I 位置没有直接的 RGB 采样。若相邻 RGB-IR 角点位置具有相同的采样依据，优先选择与原始 2×2 单元对齐的边界，与直线边缘的归属约定一致。这是一项明确的重建假设，实际边界仍可能存在一个像素的定位歧义。平坦区域拟合不意味着能够精确恢复任意纹理或斜向边缘。当前不执行传感器专用 IR 串扰校正、白平衡、训练模型推理或颜色校准。

### 方向与梯度系数

点击工具栏的滑杆图标，在图像旁打开 `demosaic-coefficients.json`。文件保存在插件的 VS Code **全局存储目录**中，升级插件后仍保留，对当前 VS Code 配置环境中的所有图像生效。保存后自动重绘已打开的 CFA 图像。JSON 或系数无效时提示错误，并保留上一次有效配置；编辑器提供字段补全、范围检查与说明。删除文件可恢复默认值，再次打开时会从 `media/demosaic-defaults.json` 重建。

检测覆盖 **0°、45°、90°、135°、180°、225°、270°、315°** 八个独立方向，按图像坐标顺时针排列：向右、右下、向下……。使用相隔两像素的同 CFA 相位样本检测梯度，并对对角线距离归一化；红蓝细化还结合固定的绿色和另一颜色通道引导值，以向量差避免不同颜色的变化互相抵消。并列方向共用各自策略的平均值。梯度方向跨越边缘，切向偏好则倾向沿着边缘插值。实际候选仍受 CFA 采样位置约束：绿色使用水平／垂直候选，红蓝使用轴向或对角线候选。

每个 `directions.<角度>.levels` 包含 2–16 个严格递增、从 0 开始的梯度阈值。默认弱、中、强三级阈值为 `0`、`0.004`、`0.016`；梯度使用黑白电平归一化后的数值，不受曝光和 Gamma 影响。等级之间连续插值，超过最高阈值时使用最后一级。默认八组系数保持旋转对称，可分别修改。

| 系数 | 作用 |
| --- | --- |
| `strength` | 梯度阈值，0–4，组内严格递增 |
| `uniform` | 均匀权重比例，0–1；越大越均匀，适合弱梯度区域 |
| `edgePower` | 跨边缘权重指数，0–4；越大越抑制颜色差异大的采样 |
| `tangentBias` | 沿边缘方向的候选偏好，0–4 |
| `regularization` | 量化步长平方下限的倍数，0.01–100 |
| `variationPenalty` | 颜色边界可信度中的平滑变化惩罚，0–10 |

这些系数作用于四种标准 Bayer 阵列及 RGB-IR 可见光重建流程，保留原始采样值。它们用于调整轻量的边缘感知算法，并非训练模型或传感器专用校准。

### 整图回归标准

[ColorChecker 测试](test/colorchecker-fixtures.test.js) 解码 Bayer RGGB / RGB-IR RGBI 的全部六个版本：12 位放入 16 位容器、紧凑 12 位和 16 位。在默认显示参数及系数下，以原始 **640×432** 尺寸与同一张 [PNG 参考图](fixtures/colorchecker24-reference.png) 比较。

- 检查尺寸、缓冲区长度和不透明 Alpha，再检查全部 **276,480 个像素／829,440 个 RGB 通道值**，包括所有角点、色块间隔和图像外边缘，不裁剪、不抽样、不排除边缘区域。
- 最大通道绝对误差要求 **≤ 1**，平均绝对误差要求 **≤ 0.1**，均以 RGB8 灰度级计。低平均误差不能掩盖单个角点的大误差；失败时报告最差像素坐标、通道、实际值和预期值。
- 当前这些测试图的整图误差为零；这只描述由 RGB8 生成的合成素材，不代表所有传感器图像的恢复精度，也不代表原生 12/16 位颜色精度。

[Bayer 测试](test/demosaic.test.js) 还覆盖阵列相位、边界奇偶位置、明暗反转、斜线、渐变和纹理。[RGB-IR 测试](test/rgbir-demosaic.test.js) 覆盖全部 24 种排列、IR 信号独立性、整幅矩形重建、不确定角点、系数行为及各可见光显示模式的一致性。原始采样值保留始终是单独的验证要求。[多方向角点测试](test/directional-corners.test.js) 覆盖八个朝向、三种夹角、四种 Bayer 相位及全部 24 种 RGB-IR 排列，并验证高位深、明暗反转、IR 独立性、系数控制和转置一致性。48×48 多边形测试图执行整图检查（RGB8 平均绝对误差 ≤ 1.5、最大通道误差 ≤ 100），中心 8×8 角点区域执行更严格的 ≤ 1 限制。远离角点的斜边保留原插值，因此该标准与保持不变的 ColorChecker 整图误差 ≤ 1 标准分别验证。

运行重建回归测试：

```sh
node --test test/demosaic.test.js test/rgbir-demosaic.test.js test/directional-corners.test.js test/colorchecker-fixtures.test.js
```

## YUV

| 采样 | 支持的存储排列 |
| --- | --- |
| 400 | 仅 Y |
| 420 | Y/U/V、Y/V/U、Y + UVUV、Y + VUVU |
| 422 | 平面、半平面，以及 YUYV、UYVY、YVYU、VYUY |
| 444 | 平面、半平面，以及 YUV、YVU、UYV、UVY、VYU、VUY |

提供 I420、YV12、NV12、NV21、I422、NV16、NV61、YUYV、UYVY、I444、NV24、NV42、P010/P012/P016 快捷预设。支持 BT.601、BT.709、BT.2020 和 full/limited range。色度使用最近邻上采样。

鼠标悬停在“颜色矩阵”或“数值范围”标签上 1 秒后显示说明，也可通过键盘聚焦标签查看，按 Esc 关闭。说明包含矩阵选择依据、8/10 bit 数值范围及误选时的显示差异；参考 [Microsoft YUV 文档](https://learn.microsoft.com/en-us/windows/win32/medfound/about-yuv-video)与 [ITU-R BT.2020](https://www.itu.int/rec/R-REC-BT.2020)。本插件的 BT.2020 选项仅使用非恒定亮度矩阵，不执行 HDR 传递函数解码或显示器色域转换。

“显示通道”可选彩色、仅 Luma（Y 灰度）、仅 Chroma（UV 色度）。Luma 忽略 U/V，Chroma 用固定 50% 亮度呈现 U/V 色彩；显示通道不改变完整 YUV 文件的每帧大小和帧边界。400 仅含 Y，不提供 Chroma 选项。

“文件内容”指定实际存储的平面：完整 YUV、仅 Y、仅 UV。`.y` 默认按 400 独立亮度文件读取；`.uv` 默认按 420 UV 交错的独立色度文件读取，不要求文件包含 Y 数据。UV 文件支持 420/422/444、UV/VU 交错及 U/V 或 V/U 平面排列。宽高始终填写完整图像尺寸，例如 320×240 的 420 UV 数据为 160×120 对 U/V 样本。独立平面也支持位深、Pitch、偏移和连续帧播放，帧大小只计算实际存在的平面。

宽高为奇数时，色度宽/高向上取整；Packed 422 的最后一个双像素组仍占完整四个样本。以 3×3 的 8-bit 420 为例，Y 为 9 B，U、V 各 4 B，总共 17 B。

## 位深与存储约定

所有 CFA 和 YUV 样本支持 **4–32 bit 无符号整数**。

- **像素深度**：每个采样值的有效位数。
- **容器大小**：每个采样点实际占用的位数，可选择 4–32 bit，且必须大于或等于像素深度。存储方式由容器大小决定，无需额外选择。自动模式通常取能容纳像素深度的最小整字节容器；已有紧密打包配置保持兼容。
- **对齐方式**：仅在容器大于像素深度时显示，位于容器大小下方。高位补零表示低位对齐、直接存值；低位补零表示高位对齐、左移后存值。例如 8 bit 像素存入 10 bit 容器时，可直接存值或左移 2 位后存值。
- **字节端序**：支持 Little Endian 和 Big Endian。非整字节容器使用连续位流，每行独立并补齐到整字节。P010 使用小端 16 bit 容器内的 10 bit 高位对齐值。
- **Pitch**：默认自动计算。底层保留包含行尾填充的自定义 Pitch 支持；Y/CFA/Packed Pitch 不再显示为输入项，色度平面 Pitch 仍可设置。UV 交错 Pitch 覆盖整个 UV 行，最后一行的填充也计入帧尺寸。

像素深度、容器大小和对齐方式均提供悬浮文档，悬停标签约 1 秒或用键盘聚焦标签即可查看，Esc 关闭。

紧密位打包不是 MIPI CSI-2 RAW10/12/14 的分组打包，也不包含 v210、带符号/浮点样本、压缩 RAW 或厂商容器格式；这些格式需要单独转换后读取。

## 读取与交互

从字节 `offset` 开始，读取当前布局要求的一帧。尺寸不足时，宽高或 offset 输入框旁静默显示提示，不弹窗，也不将残缺数据误画成完整图像。单帧模式忽略帧后多余字节，并显示忽略的大小。

“读取偏移”位于源数据配置组中，单位为字节。鼠标悬停在“读取偏移”标签上 1 秒后显示详细说明；键盘聚焦该标签也可查看，按 Esc 可关闭。

### 连续帧播放

播放栏以半透明玻璃样式悬浮在图像上方，鼠标或键盘 3 秒无操作后淡出，播放继续。鼠标在图像预览或属性面板内移动、VS Code 重新获得焦点时恢复显示。鼠标停留在播放栏任意位置、拖动进度条或编辑帧号、FPS 时保持可见；移出播放栏且结束编辑后重新开始 3 秒倒计时。公开扩展 API 无法逐次监听文件树等 VS Code 原生区域中的鼠标移动。

RAW/CFA（含 RGB-IR）和 YUV 文件可以顺序存放多张同尺寸、同布局图像。**offset 之后的可用数据严格大于两帧字节数**时，预览底部显示播放栏。恰好两帧时仍使用单帧模式；两帧加部分尾帧时可浏览前两帧。

- 单帧大小按照容器大小、采样比例、平面布局与 Pitch 计算。第 N 帧从 `offset + (N - 1) × 单帧字节数` 读取。
- 帧号从 **1** 开始。点击或拖动进度条可跳帧，也可输入帧号，按 Enter 或移开焦点确认。
- 进度条左右的“上一帧 / 下一帧”按钮每次后退或前进一帧，点击时暂停播放；首帧禁用上一帧，末帧禁用下一帧。快速连点会累计步进目标。
- “播放 / 暂停”控制连续播放，FPS 可设为 **0.1–120**，默认 **24**，设置按文件在当前会话内保留。画布获得焦点时也可用空格控制。
- 手动跳帧会暂停；到末帧自动暂停，点击“重播”从第 1 帧重新播放。隐藏预览会暂停，返回后可继续。
- 修改解析或显示属性时暂停并回到首帧；刷新会重新检查文件大小，并将帧号限制在新的有效范围内。
- 帧之间没有额外文件头或间隔。尾部不足一帧的数据会忽略，不计入完整帧数。

播放复用解码线程，每次只请求一帧，并保留最新解码帧的原始字节供像素查询，不缓存整段文件，也不积压解码任务。FPS 是目标上限，实际速度受图像尺寸、格式、存储和解码耗时影响；解码较慢时降低实际速度，不跳过帧。

本地文件使用 seek 范围读取，解码在 worker 线程执行。虚拟文件系统通过 VS Code 文件 API 读取。单帧上限 32 Mi 像素、256 MiB 输入数据；RGB/IR 并排输出宽度翻倍。远程/虚拟文件和 PNG/JPG 文件总大小限 256 MiB。本地二进制文件可以大于此限制，只读取所选帧。

顶部玻璃工具栏采用简洁线条图标。鼠标悬停在图标上并静止 2 秒后显示文字提示；移动、点击或拖动时收起。键盘聚焦也可查看提示，Esc 关闭。

- 滚轮：以鼠标为中心缩放；拖动：平移。
- 放大到最大倍率 **6400%（64×）** 时自动显示像素网格，每格对应一个图像像素；网格随平移对齐，缩小后自动隐藏。
- 像素网格显示时，图像区域顶部和左侧叠加半透明尺规，标注从 0 开始的列、行坐标。尺规与像素网格同步平移，RGB/IR 并排时两侧分别使用原图列坐标。
- 适应窗口会按主浏览区可用空间等比例放大或缩小图像，保留 16 像素边距，最大倍率仍为 64×；浏览区尺寸变化时自动重新适应。再次点击按钮恢复为 1:1 原始大小，再点一次重新适应窗口。
- `F`：适应窗口；`1`：实际像素；`+` / `-`：缩放（画布获得焦点时）。
- 指针位置显示图像坐标及原始采样值：YUV 为 `Y：… U：… V：…`；CFA 为当前阵列位置对应的 `R：…`、`G：…`、`B：…` 或 `I：…`。保留原始 4–32 位整数，不受曝光、Gamma、解马赛克和显示通道影响。400/独立 Y 没有 U/V，独立 UV 没有 Y，缺失分量显示 `—`。PNG/JPG 继续显示 RGB8。
- 仅 IR 模式的坐标对应缩小后的图像，悬浮读数来自对应的原始 IR 采样点。
- 并排模式分别标记 RGB/IR，坐标映射到原图；CFA 数值始终来自该原始阵列位置，即使正在预览插值后的 IR 通道。悬停查询只传输所指像素，按帧校验并丢弃过期结果。
- 修改源文件后，点击预览工具栏或文件列表的刷新按钮重新读取。
- 所有调整只影响预览，不写回原始图像。

## 开发与验证

### 语言资源

插件支持简体中文和英文，自动跟随 VS Code 的界面语言；未支持的语言回退为英文。更改 VS Code 显示语言并重新启动后，命令菜单、属性面板、悬浮说明、预览工具栏和错误提示使用对应语言。

文案像 Android 的字符串资源一样，通过固定的键引用，每种语言维护一个文件：

- `locales/zh-cn.json`：简体中文。
- `locales/en.json`：英文，也是缺失翻译的回退来源。

例如 `"field.endian": "字节端序"` 对应英文的 `"field.endian": "Byte Order"`，代码使用 `t('field.endian')`。动态参数写成 `{name}`，调用时传入 `t('error.integer', { min: 4, max: 32 })`，不要拼接可翻译的句子。格式标识、通道字母和单位等固定技术符号保持原样。

新增语言时复制 `locales/en.json` 为语言标记命名的 JSON 文件（例如 `locales/ja.json`），翻译值并保留键及 `{参数名}`，再运行 `npm run localize`。将新语言的 `demosaic.schema.url` 设为 `./locales/generated/demosaic-schema.<语言标记>.json`。根目录的 `package.nls*.json` 和 `locales/generated/demosaic-schema.*.json` 均由该命令生成，请勿直接编辑。`media/demosaic-schema.json` 仅维护校验规则和 `%demosaic.schema.*%` 资源键；标题、悬浮说明统一从语言资源生成，VS Code 按界面语言选取相应 schema。`npm run package` 也会自动生成并打包资源；`npm run check` 会检查生成文件是否过期，测试会检查资源键和占位符是否一致。

本地预览可分别访问 `http://127.0.0.1:4317/?lang=zh-cn` 和 `http://127.0.0.1:4317/?lang=en`，不必修改系统语言。清单翻译使用 [VS Code 的 `%key%` 与 `package.nls.json` 机制](https://github.com/microsoft/vscode-extension-samples/tree/main/i18n-sample)，运行时使用 `vscode.env.language` 选择同一套资源。
